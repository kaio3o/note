# 系統資源與行程

## 觀察方向

CPU、記憶體、磁碟 I/O 與行程狀態是基本排查面向。

```bash
top
free -h
uptime
ps aux
ps -ef --forest
pgrep process_name
kill -TERM PID
kill -KILL PID
```

## 排查流程

1. 用 `uptime`、`free -h`、`df -h` 判斷資源類型。
2. 用 `top`／`ps` 找出高耗用行程。
3. 確認行程後先用 `TERM` 優雅停止，最後才考慮 `KILL`。

## 從零開始理解

「程式」是磁碟上的檔案；「行程（process）」是程式被執行後存在於記憶體中的活動。每個行程都有 PID，父行程有 PPID，也可能使用 CPU 與記憶體。

### 先建立資源概念

- CPU：處理計算；高使用率不一定是錯誤，需看是哪個行程造成。
- 記憶體：程式執行所需空間；Linux 會使用 cache，因此 free 不等於真正可用量。
- 磁碟空間：檔案能否寫入；用 `df -h` 看檔案系統剩餘量。
- Load average：等待 CPU 或 I/O 的工作量，要配合 CPU 核心數判斷。

### 初學者排查流程

```bash
uptime
free -h
df -h
ps -eo pid,user,pcpu,pmem,stat,cmd --sort=-pcpu | head
```

先判斷哪一類資源異常，再找出對應行程。不要看到 CPU 高就立刻殺掉，先確認命令、使用者與父子關係：

```bash
ps -p <PID> -o pid,ppid,user,stat,pcpu,pmem,cmd
pstree -p <PID>
```

### 結束行程的訊號

```bash
kill -TERM <PID>
sleep 2
ps -p <PID>
kill -KILL <PID>
```

`TERM` 是「請正常結束」，程式可以清理檔案與連線；`KILL` 是強制結束，不能被攔截，只能在確認行程沒有正常停止時使用。

> [!warning] PID 會變
> 不要把昨天記下的 PID 直接套用到今天。每次操作前重新查詢並確認 `cmd`，避免結束錯誤行程。
