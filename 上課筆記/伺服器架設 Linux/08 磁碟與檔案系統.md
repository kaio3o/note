## 一、為什麼需要懂檔案系統？

資料總要有地方存放，**檔案系統**就是決定「資料怎麼放到硬碟上、怎麼找回來」的規則。這個主題很深（甚至有專門的儲存企業和學術研究），管理員要掌握的是基本概念和使用。

現代趨勢：很多系統是虛擬主機，開發者多半已有「**系統與資料分離**」的觀念，所以磁碟規劃比以前簡單——系統一顆碟，資料另外一顆虛擬碟。

## 二、什麼是檔案系統？（教室座位表比喻）

- **硬碟** = 教室；每一小塊儲存空間 = 一個**座位**；
- **檔案** = 學生；
- **作業系統** = 老師；
- **檔案系統** = **座位表**。

新學生（新檔案）來了，老師查座位表找一個空位給他坐；學生離開（刪除檔案），座位就空出來給下一個。座位表也保證**不會兩個學生坐同一個位子**（不會有兩個檔案佔同一塊空間）。

> 檔案系統 = 作業系統用來知道「資料在硬碟哪裡」的座位表。

### 索引式檔案系統（ext4、XFS 等）

進階版的座位表：不只是一張清單，而是有**索引**，可以依不同特徵（科系、年級……）快速查找，不用一個個座位翻。

- 查找、存取更快。
- 面對**大量小檔案**或**超大單一檔案**時表現較好。

### 日誌式檔案系統（Journaling）

想像每次學生換座位、進出教室，都先**在日誌本上登記一筆**。若發生意外（例如突然停電），可以翻日誌還原到一致的狀態。

運作方式：變更檔案或目錄資訊時 → **先寫到「日誌」** → 確認日誌寫好 → 才套用到真正的檔案系統。這樣突然斷電時，系統可根據日誌恢復，不會留下「做到一半」的壞資料。

支援日誌的有：ext3、ext4、**XFS**、NTFS、HFS+ 等。

> 索引式 + 日誌式 ＝ 又快又不容易壞的座位表。

### 常見檔案系統比較

| 檔案系統 | 特色 | 備註 |
|---|---|---|
| **XFS** | 大檔案、高吞吐量、可**線上擴充**；RHEL 7 起預設 | **不能縮小** |
| **ext4** | 成熟穩定，Debian／Ubuntu 預設，可擴充也可縮小 | 用 `resize2fs` |
| ext3 | 舊版，有日誌 | 逐漸淘汰 |
| FAT32／exFAT | 隨身碟相容性高 | 沒有 Linux 權限、日誌 |
| NTFS | Windows | Linux 可用 `ntfs-3g` 讀寫 |
| tmpfs | 放在記憶體的暫存檔案系統 | `/dev/shm`、`/run` |

### inode：每個檔案的「身分證」

`inode`（Index Node）是檔案系統用來記錄**檔案屬性**的資料表。每個檔案、目錄都有一個 inode，記載：

- 檔案大小
- 檔案類型（一般檔、目錄、符號連結……）
- 存取權限
- 擁有者與群組
- 建立／存取／修改時間
- **指向實際資料所在磁碟區塊（block）的指標**

對照教室比喻：inode 就是「學生個人檔案」，記著他坐哪些座位、有什麼特權。

⚠️ **重點：檔案的「名字」不在 inode 裡**，名字存在上層**目錄**裡（目錄內容 = 「名字 → inode 編號」的對照表）。這就是為什麼可以有「硬連結」：多個名字指向同一個 inode。

```bash
ls -i file       # 顯示 inode 編號
stat file        # 完整 inode 資訊
df -i            # inode 的使用量
```

> inode 數量在格式化時就決定了；用光時就算容量還有也寫不進檔案（見 [[06 系統資源與行程]]）。

## 三、Linux 的磁碟觀念

Linux **沒有 `C:\`、`D:\`**。磁碟（分割區）格式化後，是「**掛載（mount）**」到某個目錄使用。掛載就是把一個儲存空間接到目錄樹的某個位置，之後存取那個目錄就等於存取那顆磁碟。

磁碟管理有幾個層次：

```text
實體／虛擬磁碟 (/dev/sdb)
      └─ 分割區 (/dev/sdb1)  ← 在虛擬化環境常省略，整顆直接用
            └─ 檔案系統 (XFS / ext4)
                  └─ 掛載點 (/mydata)
                        └─ 使用者看到的目錄與檔案
```

> 本課程因為雲端與虛擬化環境很常「一顆虛擬碟給一個用途」，所以**直接整顆碟格式化**，不做分割。要分割時用 `fdisk`／`parted`／`gdisk`，需要彈性則用 LVM。

### 裝置命名

| 名稱 | 說明 |
|---|---|
| `/dev/sda`、`/dev/sdb` | SATA／SCSI／USB 磁碟，依序 a、b、c… |
| `/dev/sda1`、`/dev/sda2` | 該磁碟的第 1、2 個分割區 |
| `/dev/vda`、`/dev/vdb` | 虛擬化（KVM／virtio）磁碟 |
| `/dev/nvme0n1`、`/dev/nvme0n1p1` | NVMe SSD 與其分割區 |
| `/dev/mapper/rl-root` | LVM 邏輯卷（Rocky 預設安裝就是 LVM） |

## 四、新增磁碟的完整流程

假設 VM 新增了一顆 2GB 的虛擬碟，目標：掛到 `/mydata`。

### 步驟 0：先觀察，不要先修改

```bash
lsblk              # 或 lsblk -f 看檔案系統與 UUID
```

```text
NAME        MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sdb           8:0    0    2G  0 disk                ← 新碟，沒分割、沒掛載
sda           8:16   0   40G  0 disk
├─sda1        8:17   0    1G  0 part /boot
└─sda2        8:18   0   39G  0 part
  ├─rl-root 253:0    0 35.1G  0 lvm  /
  └─rl-swap 253:1    0  3.9G  0 lvm  [SWAP]
```

怎麼讀：

- `TYPE`：`disk`（整顆碟）、`part`（分割區）、`lvm`（邏輯卷）。
- `MOUNTPOINTS` 空白 = 還沒被使用 → 這就是新碟 **`/dev/sdb`**。
- 其他的 `sda` 是系統碟，**絕對不要動**。

> [!danger] 格式化之前，請再次確認裝置名稱！
> `mkfs` 會**清除目標上所有資料**。用 `lsblk` 看大小、`blkid` 看是否已有檔案系統（有 `TYPE=` 代表裡面有資料）。**打錯成 `/dev/sda` 整個系統就沒了。**

### 步驟 1：建立檔案系統（格式化）

```bash
sudo mkfs.xfs /dev/sdb
```

會印出一堆參數（block 大小、log 設定等），最後出現 `Discarding blocks...Done.` 就完成了。如果裝置上已經有檔案系統，會拒絕並提示要加 `-f` 強制，**這個提示是在保護你**，先確認再說。

ext4 的話：`sudo mkfs.ext4 /dev/sdb`。

### 步驟 2：建立掛載點

掛載點就是一個**普通的空目錄**：

```bash
sudo mkdir /mydata
```

### 步驟 3：掛載

```bash
sudo mount /dev/sdb /mydata/
```

`mount` 把「/dev/sdb 這個儲存設備」接到「/mydata 這個目錄」。

### 步驟 4：驗證

```bash
df -h /mydata
```

如果輸出有獨立的 `/mydata` 一行，且 Filesystem 是 `/dev/sdb`，代表**有獨立空間**、掛載成功；如果顯示的是 `/` 的資訊，就代表沒掛成功（只是普通目錄）。

```bash
sudo ls -l /mydata/
sudo touch /mydata/f1.txt      # 寫入測試
sudo ls -l /mydata/
```

之後就可以用第四章的權限去設定這個目錄給使用者或應用程式使用。

> [!note] 權限是跟著「檔案系統」走的
> 掛載後 `/mydata` 的擁有者、權限是存在 `/dev/sdb` 那顆檔案系統裡的（根目錄的 inode）。所以 `chown`／`chmod` 設在 `/mydata` 上，下次再掛載，設定仍然在。

### 卸載

```bash
sudo umount /mydata       # 後面接掛載點（或裝置）；沒 n 注意拼法是 umount，不是 unmount
```

卸載失敗 `target is busy` 的常見原因：你自己的 shell 還在 `/mydata` 裡面（`cd /` 離開即可），或有程式正在使用。查是誰：

```bash
sudo lsof +D /mydata
sudo fuser -vm /mydata
```

## 五、開機自動掛載：`/etc/fstab`

用 `mount` 手動掛載的，**重開機就消失**。要自動掛載，要寫進 **`/etc/fstab`**（filesystem table）。

> [!danger] fstab 寫錯可能導致開機失敗
> 開機時系統會逐行掛載 fstab 中的項目，格式錯誤或裝置不存在會卡在開機（進入 emergency mode）。**修改前一定要備份，修改後一定要用 `mount -a` 測試。**

### 流程

**1. 備份**

```bash
sudo cp -a /etc/fstab /etc/fstab_backup
```

**2. 查出裝置的 UUID**

```bash
sudo blkid /dev/sdb
# /dev/sdb: UUID="2afefffd-XXXX-YYYY-ZZZZ-e7440e1aedac" TYPE="xfs"
```

為什麼用 UUID 而不是 `/dev/sdb`？因為裝置名稱可能因為插拔順序、新增磁碟而改變（今天是 sdb，明天可能變 sdc）；**UUID 是檔案系統唯一的身分證，永遠不變**。每台機器的 UUID 都不同，要複製**自己**的。

**3. 編輯 `/etc/fstab`，在最後一行新增**

```text
UUID=2afefffd-XXXX-YYYY-ZZZZ-e7440e1aedac  /mydata  xfs  defaults  0 0
```

```bash
sudo systemctl daemon-reload     # 讓 systemd 重新讀取 fstab 產生的掛載單元
```

**fstab 六個欄位**

| # | 欄位 | 說明 | 本例 |
|---|---|---|---|
| 1 | 裝置 | `UUID=...`、`/dev/xxx`、`LABEL=...`，或遠端如 `server:/path`（NFS） | `UUID=2afe...` |
| 2 | 掛載點 | 要掛到哪個目錄 | `/mydata` |
| 3 | 檔案系統類型 | xfs、ext4、nfs… | `xfs` |
| 4 | 掛載選項 | `defaults` = rw, suid, dev, exec, auto, nouser, async | `defaults` |
| 5 | dump | 是否被 `dump` 備份（現在幾乎不用） | `0` |
| 6 | fsck 順序 | 開機檢查順序：根目錄 `1`、其他 `2`、`0` 不檢查（XFS 填 0） | `0` |

常見掛載選項：`ro`（唯讀）、`noexec`（不能執行程式，增加資安）、`nosuid`、`nofail`（**找不到裝置也不要卡住開機**，外接碟必加）、`_netdev`（網路磁碟，等網路好了再掛）。

**4. 測試前：先卸載**

```bash
df -h                  # 確認 /dev/sdb 掛在 /mydata
cd /                   # 離開 /mydata，避免 busy
sudo umount /mydata/
df -h /mydata/         # 現在應該顯示 /dev/mapper/rl-root，因為 /mydata 回到只是根目錄下的普通資料夾
```

**5. 用 `mount -a` 測試**（把 fstab 裡尚未掛載的全部掛上）

```bash
sudo mount -a
df -h /mydata/         # 又看到 /dev/sdb 了 → fstab 沒問題
```

> 如果 `mount -a` 出現錯誤，就是 fstab 有問題，**立刻修正**，不要重開機！必要時用備份還原：`sudo cp /etc/fstab_backup /etc/fstab`。

**6. 重開機最終驗證**

```bash
sudo reboot
# 開機後
df -h /mydata
```

## 六、擴充磁碟空間（線上不停機）

虛擬化平台可以隨時加大虛擬碟，XFS 又支援**掛載中直接擴充**，過去需要多道手續，現在很優雅。

### 情境

`/dev/sdb` 原本 2G，掛在 `/mydata`，現在要變 3G。

**1. 在虛擬化平台增加 1GB**（有些平台需關機，有些可以熱加；原教材示範是關機 → 加大 → 開機）

**2. 開機後確認磁碟已變大**

```bash
sudo lsblk /dev/sdb
# NAME MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
# sdb    8:16   0   3G  0 disk /mydata       ← 已經是 3G
```

（原文輸出的磁碟名稱在 `sda`／`sdb` 之間不一致，是文件筆誤，這裡以 `sdb` 為準。）

**3. 但檔案系統還是 2G！**

```bash
df -h /mydata/
# /dev/sdb   2.0G   47M  2.0G   3% /mydata      ← 還沒變
```

磁碟變大了，但裡面的**檔案系統還沒被擴展**，要手動告訴它。

**4. 擴展 XFS**

```bash
sudo xfs_growfs /mydata
# ...
# data blocks changed from 524288 to 786432
```

**5. 再次確認**

```bash
df -h /mydata/
# /dev/sdb   3.0G   54M  3.0G   2% /mydata
```

### 重點注意

- `xfs_growfs` 參數是**掛載點**，而且必須是**正在掛載使用中**才能擴展（與 ext 系列相反，`resize2fs` 用在裝置上）。
- **XFS 只能擴大，不能縮小。**
- 如果有分割區（如 `/dev/sdb1`），要先用 `growpart /dev/sdb 1` 擴分割區再 `xfs_growfs`。
- 如果是 LVM：`lvextend -l +100%FREE -r /dev/mapper/rl-root`（`-r` 會順便擴檔案系統）。

| 檔案系統 | 擴充指令 |
|---|---|
| XFS | `xfs_growfs <掛載點>`（需已掛載） |
| ext4 | `resize2fs <裝置>` |

## 七、常用磁碟指令速查

| 指令 | 作用 |
|---|---|
| `lsblk -f` | 磁碟、分割區、檔案系統、UUID、掛載點 |
| `blkid` | 看 UUID 與檔案系統類型 |
| `df -hT` | 已掛載檔案系統的用量與類型 |
| `du -sh /var/*` | 找出哪個目錄吃掉空間 |
| `findmnt` | 樹狀顯示掛載來源與選項 |
| `mount` / `umount` | 掛載／卸載 |
| `mkfs.xfs` / `mkfs.ext4` | **格式化（破壞性）** |
| `xfs_growfs` | 擴充 XFS |
| `mount -a` | 依 fstab 掛載（測試用） |

> [!warning] 兩個大忌
> ① `mkfs` 前不確認裝置 → 資料全毀。② 改完 `fstab` 不測試就重開機 → 開不了機。
