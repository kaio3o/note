# 磁碟與檔案系統

## 管理流程

找出裝置 → 建立或確認檔案系統 → 建立掛載點 → 掛載 → 確認容量與權限 → 必要時設定 `/etc/fstab`。

```bash
lsblk
blkid
df -h
du -sh /var/log/*
mount
mount /dev/sdb1 /mnt/data
umount /mnt/data
```

> 執行 `mkfs` 會破壞資料；格式化前必須確認裝置名稱與備份狀態。

## 從零開始理解

磁碟管理有幾個不同層次：

1. 實體或虛擬磁碟，例如 `/dev/sdb`。
2. 分割區，例如 `/dev/sdb1`。
3. 檔案系統，例如 XFS、ext4。
4. 掛載點，例如 `/mnt/data`。
5. 使用者看到的目錄與檔案。

「掛載」不是複製資料，而是把某個檔案系統接到目錄樹的一個位置。

### 先觀察，不要先修改

```bash
lsblk -f
blkid
df -hT
findmnt
du -sh /var/*
```

- `lsblk -f`：看裝置、檔案系統、UUID。
- `df -hT`：看已掛載檔案系統的使用量。
- `du -sh`：找出哪個目錄吃掉空間。
- `findmnt`：確認實際掛載來源。

### 測試掛載的基本流程

假設已確認裝置是 `/dev/vdb1`：

```bash
sudo mkdir -p /mnt/data
sudo mount /dev/vdb1 /mnt/data
findmnt /mnt/data
df -hT /mnt/data
sudo umount /mnt/data
```

### 永久掛載的觀念

手動 `mount` 重開機後可能消失；要永久掛載通常在 `/etc/fstab` 使用 UUID。修改後先執行：

```bash
sudo mount -a
findmnt
```

`mount -a` 沒有錯誤，才比較適合考慮重開機驗證。

> [!danger] `mkfs` 會清除資料
> `mkfs.xfs /dev/sdb1` 是格式化，不是「修復磁碟」。執行前必須用 `lsblk`、備份與裝置大小再次確認目標。
