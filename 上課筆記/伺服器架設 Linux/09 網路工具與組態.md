# 網路工具與組態

## 常用診斷

```bash
ip addr
ip route
ss -tulpen
ping -c 4 8.8.8.8
curl -I https://example.com
dig example.com
hostnamectl
```

## 排查順序

1. `ip addr`：確認介面與 IP。
2. `ip route`：確認預設閘道。
3. `ping`：測試連線。
4. `dig`：確認 DNS。
5. `ss`：確認服務監聽的 IP 與 Port。
6. 檢查防火牆與服務狀態。

## 從零開始理解

網路排查要分層進行，不要一看到網站打不開就直接重設網路：

1. 網路介面是否啟用？
2. 是否取得 IP？
3. 是否有預設路由？
4. DNS 能否把名稱轉成 IP？
5. 目標服務是否監聽 Port？
6. 防火牆或服務設定是否阻擋？

### 一步一步檢查

```bash
ip -br link
ip -br addr
ip route
ping -c 4 <default-gateway>
ping -c 4 8.8.8.8
dig +short example.com
curl -I https://example.com
```

解讀方式：

- 連閘道都不通：先看介面、IP、路由。
- IP 可通但網域不通：可能是 DNS。
- DNS 有結果但 `curl` 失敗：可能是服務、Port、TLS 或防火牆。
- 本機服務是否有監聽：`ss -lntup`。

### IP 與 Port 的差異

IP 用來找「哪一台主機」；Port 用來找「那台主機上的哪一個服務」。例如 `192.168.1.10:22` 通常代表該主機的 SSH 服務。

```bash
ss -lntp
curl -v http://127.0.0.1:8080/
```

`127.0.0.1` 是本機回送位址；服務只監聽它時，其他主機無法連線，即使服務在本機正常。

> [!tip] 先記錄再修改
> 修改 IP、路由或 NetworkManager 設定前，先保存 `ip addr`、`ip route` 與連線名稱；遠端操作時錯誤設定可能會讓 SSH 立即中斷。
