## 一、先建立概念

### IP 與 Port 的差別

- **IP**：找「哪一台主機」。
- **Port（連接埠）**：找「那台主機上的哪一個服務」。

例如 `192.168.1.10:22` = 192.168.1.10 這台主機上的 SSH 服務。

| Port | 常見服務 |
|---|---|
| 22 | SSH |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 123 (UDP) | NTP |
| 3306 | MariaDB／MySQL |

`127.0.0.1`（`localhost`）是「本機回送位址」：服務**只監聽 127.0.0.1** 時，其他主機連不進來，即使服務在本機運作正常。

### 網路問題要「分層」排查（超重要）

不要一看到「網站打不開」就亂重設網路。照順序，從底層往上：

| 層次 | 要問的問題 | 工具 |
|---|---|---|
| 1. 介面 | 網卡有啟用（UP）嗎？ | `ip -br link` |
| 2. IP | 有拿到 IP 嗎？ | `ip -br addr` |
| 3. 路由 | 有預設閘道嗎？ | `ip route` |
| 4. 連通性 | 連得到閘道／外網嗎？ | `ping` |
| 5. 名稱解析 | 網域名稱能轉成 IP 嗎？ | `host`／`dig` |
| 6. 服務 | 對方（或本機）的 Port 有開嗎？ | `ss`、`curl` |
| 7. 防火牆 | 有被擋嗎？ | `firewall-cmd` |

解讀結果：

- 連**閘道**都不通 → 看介面、IP、路由（第 1~3 層）
- IP 通、**網域名稱**不通 → 多半是 **DNS**
- DNS 有結果，但 `curl` 失敗 → 服務、Port、TLS 或防火牆

## 二、網路診斷工具

### `ip`：看介面、IP、路由

取代老舊的 `ifconfig`、`route`（minimal 安裝已不一定有）。

```bash
ip link show           # 網卡清單（第二層）；-br 簡潔版
ip -br link
ip addr                # IP 位址；也可 ip a
ip -br addr
ip route               # 路由表；"default via x.x.x.x" 就是預設閘道
ip -s link             # 加上收送封包統計
```

`ip link show` 範例：

```text
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 ... state UNKNOWN
2: enp5s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 9000 ... state UP
    link/ether 56:6f:8c:e7:00:67 brd ff:ff:ff:ff:ff:ff
```

| 項目 | 說明 |
|---|---|
| `lo` | loopback 本機回送，永遠存在 |
| `enp5s0`／`ens192` | 實體（或虛擬）網卡的名稱（可預測的命名規則） |
| `UP`／`LOWER_UP` | 啟用 / 線路有接 |
| `link/ether` | MAC 位址 |

### `ping`：測試連通性

```bash
ping -c 4 example.com
```

`-c 4` 表示只送 4 次（預設會一直 ping 到你按 `Ctrl+C`）。輸出：

```text
PING example.com (93.184.216.34) 56(84) bytes of data.
64 bytes from 93.184.216.34: icmp_seq=1 ttl=52 time=130 ms
...
4 packets transmitted, 4 received, 0% packet loss, time 3005ms
rtt min/avg/max/mdev = 130.773/132.960/133.770/1.315 ms
```

| 資訊 | 說明 |
|---|---|
| IP | 名稱被解析成的 IP（順便驗證 DNS 有沒有運作） |
| `icmp_seq` | 第幾個封包 |
| **TTL** | 封包最多還能經過幾個路由器；從 TTL 可大致猜對方作業系統（64 → Linux、128 → Windows） |
| **RTT**（`time`） | 來回時間，越小越好 |
| **packet loss** | 丟包率，評估穩定性 |
| `rtt min/avg/max/mdev` | 最小／平均／最大延遲與抖動 |

> [!warning] ping 不通 ≠ 主機掛了；ping 通 ≠ 服務正常
> `ping` 用 **ICMP**，很多防火牆會擋 ICMP。所以：
> - ping 不通，主機可能還在，只是不回應。
> - ping 通了，只代表「網路層可達」，網站服務可能是壞的。
> 這時要改用 `curl` 這類**服務層**工具測試。

排查建議順序：ping 閘道 → ping `8.8.8.8`（不用 DNS）→ ping 網域名稱。這樣能區分是「網路」還是「DNS」問題。

### `ss`：看 Port 和連線（取代 `netstat`）

`ss` 查 **socket 狀態**，速度快、選項多。Minimal 安裝的 EL7 以後沒有 `netstat`，用 `ss`。

| 參數 | 說明 |
|---|---|
| `-t` | TCP |
| `-u` | UDP |
| `-l` | 只顯示**監聽中**（LISTEN） |
| `-n` | 不要解析名稱，直接顯示數字 IP 和 Port |
| `-p` | 顯示**哪個行程**在用（通常要 sudo） |
| `-e` | 詳細資訊 |
| `-a` | 全部（含 listening 和 non-listening） |

**看本機開了哪些 Port：**

```bash
sudo ss -ntulp
```

```text
Netid State  Recv-Q Send-Q  Local Address:Port  Peer Address:Port
tcp   LISTEN 0      128               *:22               *:*     users:(("sshd",pid=5351,fd=3))
tcp   LISTEN 0      100       127.0.0.1:25               *:*     users:(("master",pid=5822,fd=13))
tcp   LISTEN 0      128              :::22              :::*     users:(("sshd",pid=5351,fd=4))
```

| 欄位 | 說明 |
|---|---|
| `Netid` | 協定（tcp／udp） |
| `State` | `LISTEN` = 正在等人連線；`ESTAB` = 已建立連線 |
| `Recv-Q／Send-Q` | 接收／傳送佇列，持續大於 0 可能代表處理不過來 |
| `Local Address:Port` | 本機位址:Port。`*` 或 `0.0.0.0` = **所有 IP**；`127.0.0.1` = **只有本機**；`:::` = IPv6 所有位址 |
| `Peer Address:Port` | 對方（LISTEN 時是 `*:*`，代表任何人都可以連） |
| `users` | 哪個行程（名稱、PID） |

**資安觀點**：管理員一定要知道**哪些 Port 開在對外的 IP 上**。上例 sshd 對外（`*:22`），而 postfix(master) 的 25 只在 `127.0.0.1`，外部連不到，安全。

**檢查服務有沒有真的聽在正確的 Port：** `ss -lntp | grep ':80'`

**看目前連線（誰連我、我連誰）**：去掉 `-l` 和 `-p`：

```bash
sudo ss -ntu
```

```text
Netid State Recv-Q Send-Q  Local Address:Port    Peer Address:Port
tcp   ESTAB 0      0       192.168.5.30:80       192.168.3.80:52667
```

→ 有人從 192.168.3.80 連到我的 80 Port。看到不認識的 `ESTAB` 連線要提高警覺。

### `host`：DNS 查詢（最直覺）

`host` 屬於 `bind-utils` 套件（同包還有 `dig`、`nslookup`），若沒有指令：

```bash
sudo dnf install -y bind-utils
```

老師的觀點：大部分情況只要確認「**名稱和 IP 對不對得起來**」，`host` 最直觀。

```bash
host example.com
# example.com has address 93.184.216.34
# example.com has IPv6 address 2606:2800:220:1:248:1893:25c8:1946
```

- `has address` → **A 記錄**（IPv4）
- `has IPv6 address` → **AAAA 記錄**

**反解（由 IP 查名稱，PTR 記錄）：**

```bash
host 93.184.216.34
# 34.216.184.93.in-addr.arpa domain name pointer example.com.
```

不是每個 IP 都有反解，看到 `not found: 3(NXDOMAIN)` 代表該 IP 沒有設定反向對應。

**指定用某一台 DNS 查（驗證自己的 DNS 是否正確）：**

```bash
host example.com 8.8.8.8
```

進階想看更多（MX、NS、TXT、追蹤過程）可用 `dig`：

```bash
dig +short example.com
dig MX example.com
dig @8.8.8.8 example.com
```

（更多 DNS 記錄見 [[期末練習與DNS補充]]。）

### `traceroute`：封包經過哪些路由器

```bash
sudo traceroute -n example.com
```

```text
traceroute to example.com (93.184.216.34), 30 hops max, 60 byte packets
 1  10.1.1.254  0.151 ms  0.164 ms  0.133 ms
 2  15.62.X.Y   4.738 ms ...
 ...
11  93.184.216.34  130.779 ms ...
```

每一行是一個「**跳點（hop）**」，三個時間是三次測試的延遲。可以用來找**延遲突然變大**或**路徑中斷**的位置。

| 參數 | 說明 |
|---|---|
| `-n` | 只顯示 IP，不反解（快很多） |
| `-I` | 用 ICMP Echo（預設是 UDP） |
| `-T` | 用 TCP SYN，常用來**穿越擋 ICMP/UDP 的防火牆**（通常搭配 `-p 443`） |
| `-p` | 指定 Port |

看到 `* * *` 代表那一跳沒回應（可能被防火牆擋，不一定是故障）。其他選擇：`tracepath`（不需 root）、`mtr`（持續更新的 traceroute+ping）。

### `curl`：服務層測試

```bash
curl -I https://example.com        # 只看 HTTP 標頭（狀態碼）
curl -v http://127.0.0.1:8080/     # 詳細過程
curl -L url                        # 跟著轉址
curl -o file.html url              # 存檔
curl ifconfig.me                   # 查自己的對外 IP
```

`curl` 通表示：DNS、路由、防火牆、服務、TLS **全部都 OK**，是最完整的「通不通」測試。

### 小結：診斷流程（建議背起來）

```bash
ip -br addr                  # ① 有 IP 嗎
ip route                     # ② 有預設閘道嗎
ping -c 4 <default-gateway>  # ③ 通閘道嗎
ping -c 4 8.8.8.8            # ④ 通外網嗎（不靠 DNS）
host example.com             # ⑤ DNS 正常嗎
curl -I https://example.com  # ⑥ 服務正常嗎
ss -tulpen                   # ⑦ 本機服務有在聽嗎
```

## 三、設定網路組態

### 為什麼用 NetworkManager？

以前在 Enterprise Linux 設定網路要編輯很多檔案（`ifcfg-eth0` 等），容易出錯，綁定（bonding）、LACP 等進階設定更困難。**RHEL 7 開始改用 NetworkManager** 取代傳統 `network` 服務。

特點：

- 提供文字介面 `nmtui` 與指令 `nmcli` 兩種管理工具
- 支援有線、Wi-Fi、VPN 等
- 自動依環境與優先級管理連線
- 支援進階設定（IP、DNS、路由）

> [!note] 設定檔在哪？
> 原教材說設定檔會放在 `/etc/sysconfig/network-scripts/`（RHEL 7／8 的 ifcfg 格式）。**RHEL 9／Rocky 9 起改為 keyfile 格式**，位置在 `/etc/NetworkManager/system-connections/*.nmconnection`。不論哪一種，老師建議：**不要直接手改檔案，用 nmtui／nmcli 產生**，格式一致、不易出錯。
>
> DNS 也一樣：傳統要手改 `/etc/resolv.conf`，現在由 NetworkManager 統一管理（`resolv.conf` 開頭會註明 "Generated by NetworkManager"），用工具設定即可。

### 課堂環境（NTUB）

| 主機 | 設定 |
|---|---|
| ServerA／Server1 | 在 VMware Player **新增第 2 張網卡**，模式選 **Bridge**；網卡名稱用 `ip link show` 確認；IP：`172.16.X.31`，遮罩 `255.255.255.0`（CIDR `/24`） |
| ServerB／Server2 | IP：`172.16.X.32`，遮罩 `255.255.255.0`（`/24`） |

> `X` 是依教室分配的網段數字。課堂上若使用 VirtualBox，有一項要**關閉 VirtualBox 的網路**（避免衝突）。Server1 與 Server2 的網卡在教材範例中名稱是 `ens192`。
>
> 測試目標：Server1 ping 得到 Server2，Server2 ping 得到 Server1。

### 方式 A：`nmtui`（文字介面，新手推薦）

先用 `ip link show` 找出要設定的網卡名稱（例如 `enp5s0`）。

```bash
sudo nmtui
```

用鍵盤 ↑↓←→、`Tab`、空白鍵、Enter 操作。

1. 選 **Edit a connection**。
2. 找到網卡名稱，選 **Edit...**。
3. **IPv4 CONFIGURATION** 選 **`<Manual>`**，在 `Addresses` 填 `172.16.X.31/24`（`Gateway`、`DNS servers` 視需求填）。**確認勾選 `Automatically connect`**，最後 **OK**。
4. **Back** 回上層。
5. 選 **Activate a connection**。
6. 選剛設好的連線，執行 **Deactivate**（停用）。
7. 再選一次 **Activate**，讓設定生效（名稱前面出現 `*` 就代表已啟用）。
8. **Quit** 離開。

> [!danger] 遠端操作時，第 6 步會讓你斷線！
> Deactivate 會把網卡關掉，如果你是用 SSH 連進來的，連線立刻中斷，也無法再把它打開。**這個流程要在實體機或 VM 控制台執行**。遠端時請用 `nmcli connection up`（見下方）。

驗證：

```bash
ip addr          # inet 欄位看到你設定的 IP 就是成功了
ping -c 4 172.16.X.32
```

### 方式 B：`nmcli`（指令，熟悉後最快）

先查有哪些連線：

```bash
sudo nmcli connection show
# NAME     UUID                                  TYPE      DEVICE
# enp5s0   d2d68553-f97e-7549-7a26-b34a26f29318  ethernet  enp5s0
```

常用參數：

| 參數 | 說明 |
|---|---|
| `ipv4.addresses` | IP／遮罩（CIDR），如 `192.168.1.30/24` |
| `ipv4.gateway` | 預設閘道 |
| `ipv4.dns` | DNS 伺服器（多個用空白或逗號分隔） |
| `ipv4.method` | `manual`（固定 IP）／`auto`（DHCP） |
| `connection.autoconnect` | 開機自動啟用（`yes`） |

修改（`\` 是換行接續符號）：

```bash
sudo nmcli connection modify enp5s0 \
  ipv4.addresses 192.168.1.30/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 8.8.8.8 \
  ipv4.method manual \
  connection.autoconnect yes
```

套用：

```bash
sudo nmcli connection up enp5s0
```

> `connection up` 直接重新啟用，不會像 `nmtui` 先 Deactivate 再 Activate，所以**遠端設定也不會失去連線**（除非你把自己的 IP 改成別的 IP，那連線當然就換了，要小心）。

其他常用：

```bash
nmcli device status                 # 網卡狀態
nmcli connection show enp5s0        # 看某連線所有參數
nmcli connection modify enp5s0 +ipv4.addresses 172.16.1.31/24   # 追加第二個 IP
nmcli connection reload             # 重新讀取設定檔
nmcli device show enp5s0 | grep -E 'IP4|DNS'
```

進階：[Red Hat 官方文件 - 用 nmcli 設定乙太網路](https://access.redhat.com/documentation/en-us/red_hat_enterprise_linux/8/html/configuring_and_managing_networking/configuring-an-ethernet-connection_configuring-and-managing-networking)

### 設定完怎麼確認？

```bash
ip -br addr                  # IP 對不對
ip route                     # 預設閘道有沒有
cat /etc/resolv.conf         # DNS 有沒有
ping -c 4 <同網段的另一台>     # 同網段通不通
ping -c 4 <gateway>           # 閘道通不通
```

> [!tip] 先記錄再修改
> 改 IP、路由前，先保存 `ip addr`、`ip route` 與連線名稱（`nmcli connection show`）。遠端操作時一旦設錯，SSH 會立即中斷，要靠主控台救援。
