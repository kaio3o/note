## 一、為什麼時間這麼重要？

時間不只是螢幕右下角的數字，很多系統都依賴它：

| 場景 | 依賴時間的原因 |
|---|---|
| **網購** | 時間戳記用來排「加入購物車 → 結帳 → 付款」的順序，確保交易完整一致 |
| **雙因素驗證（2FA／OTP）** | 一次性密碼是用**時間**算出來的，兩邊時間差太多就驗證失敗 |
| **日誌（log）** | 出事後要靠時間軸還原事件順序；多台主機時間不一致就拼不起來 |
| **憑證（SSL/TLS）** | 憑證有「生效日、到期日」，時間錯了會被判定無效或過期 |
| **排程、備份、資料庫交易** | 在錯的時間執行，或交易紀錄先後顛倒 |

> 時間不準 → 資料分析錯誤、系統故障、甚至資料遺失。**所以「確保時間準確」是資訊基礎設施不可忽視的一環。**

## 二、基本名詞

### UTC：世界協調時間

- 伺服器內部（不論實體機或 VM）幾乎都以 **UTC**（Coordinated Universal Time）為基準，它是全球的時間標準，精確又穩定。
- 台灣是 **UTC+8**，所以台北 14:00 = UTC 06:00。
- 這樣做的好處：跨國的主機之間不會因為時區搞混，顯示給人看的時候再「轉成本地時間」就好。

### 兩種時間來源

| | 硬體時間（**RTC**，Real-Time Clock） | 系統時間（System Clock） |
|---|---|---|
| 在哪 | 主機板上的晶片，靠**獨立電池**供電 | 作業系統核心維護 |
| 關機後 | 持續走 | 消失 |
| 用途 | 開機時給作業系統「第一個時間」 | 檔案時間戳記、排程、日誌 |

**開機時**，作業系統會讀 RTC 設成系統時間；之後系統時間自己跑。所以如果 RTC 電池沒電、或 RTC 跟系統時間不一致，**重開機後時間就可能亂掉**。

### 時間格式

常見日期寫法：

| 格式 | 範例 |
|---|---|
| **ISO 8601（國際標準）** | `2023-08-18` |
| 美國式 MM/DD/YYYY | `08/18/2023` |
| 歐洲式 DD/MM/YYYY | `18/08/2023` |
| 長格式 | `August 18, 2023` |

時間：24 小時制 `14:30:15`、12 小時制 `2:30:15 PM`。ISO 8601 完整寫法：`2023-08-18T14:30:15+08:00`（`T` 分隔日期與時間，`+08:00` 是時區偏移）。

> [!tip] 寫腳本、log 一律用 ISO 8601
> 不會有 01/02 到底是 1 月 2 日還是 2 月 1 日的疑惑，而且**直接按文字排序就是時間先後順序**。

## 三、查看與修改系統時間

### `timedatectl`：完整時間狀態

```bash
timedatectl
```

```text
               Local time: Sun 2022-10-23 14:19:11 CST
           Universal time: Sun 2022-10-23 06:19:11 UTC
                 RTC time: Sun 2022-10-23 14:19:09
                Time zone: Asia/Taipei (CST, +0800)
System clock synchronized: no
              NTP service: inactive
          RTC in local TZ: no
```

| 欄位 | 白話說明 |
|---|---|
| `Local time` | 本地時間（含時區縮寫，CST = 台北標準時間 +8） |
| `Universal time` | UTC 時間 |
| `RTC time` | 硬體時鐘的時間 |
| `Time zone` | 目前設定的時區 |
| `System clock synchronized` | **有沒有跟外部時間來源同步** |
| `NTP service` | 校時服務有沒有在跑 |
| `RTC in local TZ` | RTC 是用本地時間（yes）還是 UTC（no，Linux 的標準做法） |

> [!note] 與 Windows 雙系統時間差 8 小時？
> Windows 預設把 RTC 當成「本地時間」，Linux 預設當成 UTC，一起用就會差 8 小時。解法：`timedatectl set-local-rtc 1`（讓 Linux 配合），或改 Windows 登錄檔。

### `date`：快速查看與格式化

```bash
date
# Fri Aug 18 14:30:15 CST 2023

date +"%Y"          # 2023  （+ 後面是自訂格式，%Y = 四位數年）
date '+%F %T %z'    # 2023-08-18 14:30:15 +0800
date +"%Y%m%d_%H%M%S"   # 20230818_143015 （幫備份檔命名很常用）
```

常用格式碼：

| 碼 | 意義 | 碼 | 意義 |
|---|---|---|---|
| `%Y` | 年（4 位） | `%H` | 時（24 小時制） |
| `%m` | 月 | `%M` | 分 |
| `%d` | 日 | `%S` | 秒 |
| `%F` | `%Y-%m-%d` | `%T` | `%H:%M:%S` |
| `%z` | 時區偏移 | `%s` | 自 1970-01-01 起的秒數 |

完整清單看 `man date` 的 FORMAT 章節。

### `timedatectl` vs `date`

| | `timedatectl` | `date` |
|---|---|---|
| 資訊量 | 完整（時區、NTP、RTC） | 簡單 |
| 適合 | 檢查系統時間設定 | 快速查時間、**輸出特定格式**（腳本） |
| 修改時間 | 格式直觀 | 格式較複雜 |

### 手動調整時間

```bash
sudo timedatectl set-time "2022-01-10 11:00:00"
timedatectl      # Local time 變成 2022-01-10 11:00:xx
```

> [!warning] 要先關掉 NTP 才能手動設時間
> 如果 NTP 校時是開啟的，`set-time` 會失敗（`Failed to set time: Automatic time synchronization is enabled`）。先 `sudo timedatectl set-ntp false`，改完後別忘了再 `set-ntp true`。**正式環境幾乎不手動改時間**，用 NTP 才對。

### 修改時區

出口公司的系統可能放在世界各地，所以需要改時區。

```bash
timedatectl list-timezones              # 列出全部（很長，可搭配 grep）
timedatectl list-timezones | grep -i taipei    # Asia/Taipei
sudo timedatectl set-timezone America/New_York
timedatectl
# Local time: Sun 2022-10-23 02:37:22 EDT      ← 變成紐約時間
# Universal time: ... 06:37:22 UTC             ← UTC 不變！
# Time zone: America/New_York (EDT, -0400)
sudo timedatectl set-timezone Asia/Taipei   # 改回台灣
```

重點：**改時區只改「顯示」，UTC 時間不變**。

### 保存到硬體時間：`hwclock`

```bash
sudo hwclock -r      # --show，讀取硬體時間
sudo hwclock -w      # --systohc，把「系統時間 → 寫到硬體」
sudo hwclock -s      # --hctosys，反過來「硬體 → 系統」
```

為什麼要同步？如果兩者不同步，每次重開機系統時間就會被設成不對的值，造成：

- 檔案時間戳記錯誤
- 排程在錯的時間跑
- SSL/TLS 憑證驗證失敗
- 資料庫交易、log 不一致
- 跨網路對時間敏感的操作出錯

所以「改完系統時間／時區後做一次 `hwclock -w`」是建議流程。若修改前後看起來沒變，代表兩者本來就一致，沒問題。

> [!note] 其實有 NTP 就不用煩惱
> systemd 與 chrony 啟用 NTP 後，核心會每 11 分鐘左右自動把系統時間同步到 RTC，通常不用手動 `hwclock -w`。

## 四、NTP 網路校時

### 為什麼不手動調？

一個系統通常 2 台主機起跳，企業可能有 10 台、幾百台。每台手動調：

- 費時、不可行；
- 小誤差累積就會造成資料不一致、嚴重故障。

→ 讓所有主機向**同一個時間來源**同步。這就是 **NTP（Network Time Protocol）**，使用 **UDP/123**。

### Chrony：RHEL 系的校時軟體

RHEL 7 開始以 **chrony** 取代傳統 `ntp`，優點：

- 可以同時向**多個**時間來源校時
- 自動調整校時頻率
- 可同時當用戶端與伺服器（供其他主機同步）
- 在網路不穩定、VM 時鐘亂跳的環境表現更好

```bash
sudo dnf install -y chrony           # 安裝（minimal 安裝通常已內建）
sudo systemctl enable --now chronyd  # 開機自動啟動 + 現在啟動
```

> 服務名稱是 `chronyd`（背後的 daemon），用戶端工具是 `chronyc`（c = client）。`enable --now` 的意義見 [[11 systemd 與日誌]]。

查看校時來源：

```bash
sudo chronyc sources        # 加 -v 可看欄位說明
```

```text
210 Number of sources = 4
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
^* server1b.meinberg.de          2  10   377   517  -1604us[-1576us] +/-  109ms
^+ purple.bonev.com              2  10   177  273m    -16ms[  -16ms] +/-  212ms
```

| 欄位 | 說明 |
|---|---|
| `M`（第一個字元） | 來源模式：`^` 伺服器、`=` 對等 |
| `S`（第二個字元） | 狀態：**`*` 目前正在同步的**、`+` 可用的候選、`-` 被排除、`?` 失去連線／不可信 |
| `Stratum` | 距離原子鐘幾層，越小越準 |
| `Poll` | 輪詢間隔（2 的次方秒） |
| `Reach` | 最近 8 次連線成功與否（八進位，`377` = 全成功） |
| `LastRx` | 距離上次收到回應的時間 |

其他好用的：

```bash
chronyc tracking     # 目前與時間來源的誤差、同步狀態
chronyc makestep     # 立刻強制校正（誤差很大時）
chronyc sourcestats  # 各來源的統計
```

### 指定同步來源（企業內部校時）

資安考量下，企業主機常被限制不能直接上網，所以內部會自己架時間伺服器（最常見是 **Windows Active Directory**），把 Linux 的校時來源指向它，內部時間就一致了。

只需要修改一個檔：`/etc/chrony.conf`。

```bash
sudo vi /etc/chrony.conf
```

把預設的 `pool ...` 或 `server ...` 行註解掉，改成：

```text
server 172.16.6.3 iburst
```

- `iburst`：第一次連不上或剛啟動時，快速連續送出多個封包，讓同步更快完成。

存檔後**重啟服務才會生效**：

```bash
sudo systemctl restart chronyd
sudo chronyc sources
```

```text
210 Number of sources = 1
^* 172.16.6.3                    3   6    17    11  -2939ns[  -32us] +/- 9513us
```

用 `timedatectl` 驗證：

```text
System clock synchronized: yes
              NTP service: active
```

兩個都變成 `yes`／`active` 就成功了。

### 課程演練：改用台灣國家時間

把同步來源改為 **`time.stdtime.gov.tw`**（台灣標準時間，由電信研究院提供）：

```text
server time.stdtime.gov.tw iburst
```

```bash
sudo systemctl restart chronyd
chronyc sources -v
timedatectl
```

> [!tip] 常見的台灣校時來源
> `time.stdtime.gov.tw`、`tock.stdtime.gov.tw`、`watch.stdtime.gov.tw`，也可用 `tw.pool.ntp.org`。

### 如果你的主機要「當校時伺服器」給別人

在 `/etc/chrony.conf` 加：

```text
allow 192.168.1.0/24
```

並在防火牆放行 UDP 123：

```bash
sudo firewall-cmd --add-service=ntp --permanent
sudo firewall-cmd --reload
```

## 五、系統排程：cron

### 為什麼需要排程？

排程是自動化的基礎：**在指定時間自動執行任務**，不必人工啟動。例子：每晚 10 點備份、每週一早上 9 點更新系統、每分鐘檢查服務。

Linux 最常用的是 **cron**（背後的服務叫 `crond`）。

### cron 的時間格式

```text
┌───────── 分 (0 - 59)
│ ┌─────── 時 (0 - 23)
│ │ ┌───── 日 (1 - 31)
│ │ │ ┌─── 月 (1 - 12，或 jan,feb...)
│ │ │ │ ┌─ 星期 (0 - 6，日=0 或 7；或 sun,mon...)
│ │ │ │ │
* * * * *  指令
```

| 符號 | 意義 | 範例 |
|---|---|---|
| `*` | 每一個 | `* * * * *` = 每分鐘 |
| `,` | 列舉 | `1,15` = 第 1 和 15 |
| `-` | 範圍 | `1-5` = 週一到週五 |
| `/` | 間隔 | `*/5` = 每 5 單位 |

**範例**

| 設定 | 意義 |
|---|---|
| `0 2 1 * *` | 每月 1 號 02:00 |
| `0 0 29 2 *` | 每年 2 月 29 日 00:00（閏年才會執行） |
| `30 2 * * 6,7` | 每週六、日 02:30 |
| `*/10 * * * *` | 每 10 分鐘 |
| `0 9 * * 1` | 每週一 09:00 |
| `@reboot` | 每次開機時執行 |

### 兩種排程：系統 vs 使用者

| | 系統排程 | 使用者排程 |
|---|---|---|
| 位置 | `/etc/crontab`、`/etc/cron.d/` | `crontab -e`（存在 `/var/spool/cron/使用者`） |
| 欄位數 | **7 欄**：分 時 日 月 週 **執行身份** 指令 | **6 欄**：分 時 日 月 週 指令（身份就是自己） |
| 編輯 | 直接 `vi`，**存檔即生效** | `crontab -e`（存檔後自動安裝） |
| 適合 | 全域／統一的維運作業（監控、稽核） | 個人工作 |

另外系統預設有 `/etc/cron.hourly/`、`cron.daily/`、`cron.weekly/`、`cron.monthly/` 目錄，把腳本丟進去就會定期執行（由 `run-parts` 呼叫）。

### 查看排程

```bash
crontab -l                  # 看自己的（沒設定會顯示 no crontab for student）
sudo crontab -l -u alice    # 看別人的
sudo cat /etc/crontab       # 看系統排程
```

`/etc/crontab` 預設內容有：

```text
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
```

> [!warning] cron 的環境很「乾淨」
> cron 執行時**幾乎沒有環境變數**，`PATH` 只有幾個目錄，也不會載入你的 `.bashrc`。所以腳本裡請：① 用**絕對路徑**；② 在腳本開頭設好需要的環境變數；③ 輸出重導到日誌，不然會被寄信給 `MAILTO` 的人。

### 練習 1：系統排程（每分鐘把 /etc 列表存檔）

```bash
sudo vi /etc/crontab
```

在最後加一行（有「執行身份」欄位 root）：

```text
* * * * * root (ls /etc > /tmp/etc.txt)
```

等 1 分鐘後：

```bash
ls -lh /tmp/etc.txt
```

### 練習 2：使用者排程（每分鐘記錄時間）

```bash
crontab -l                    # 先看有沒有
ls -l /tmp/systime.txt        # 還不存在
crontab -e                    # 會用 vi 開啟，加入下面這行
```

```text
* * * * * (date >> /tmp/systime.txt)
```

這裡是用 `>>` 附加，每分鐘多一行：

```bash
cat /tmp/systime.txt
# Sun Oct 23 14:59:01 CST 2022
# Sun Oct 23 15:00:01 CST 2022
```

**解除排程**：再執行 `crontab -e` 把那一行刪除；或 `crontab -r`（⚠️ 清空**全部**排程，連確認都不會問）。

### 排程記錄

不論成功失敗，cron 都會記錄在 `/var/log/cron`：

```bash
sudo cat /var/log/cron
# Oct 23 14:59:01 localhost CROND[1851]: (root) CMD ((date >> /tmp/systime.txt))
```

排程沒跑時，**先看這個檔案**確認 cron 有沒有嘗試執行；`journalctl -u crond` 也可以。

### 實務範本

```cron
# 每天 02:00 備份，成功與失敗都記到 log
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
```

- 腳本用絕對路徑、要有執行權限（`chmod +x`）。
- `>> ... 2>&1` 附加並同時記錄錯誤，見 [[05 訊息重導與管線]]。
- 先手動執行腳本確認沒問題，再放進排程。

### 進階：systemd timer

新系統更常把排程做成 **systemd timer**：能設定服務相依，輸出自動進 journal。

```bash
systemctl list-timers          # 查看目前的 timers
```

## 六、本章小抄

```bash
timedatectl                              # 時間狀態總覽
sudo timedatectl set-timezone Asia/Taipei
sudo timedatectl set-ntp true            # 啟用 NTP
chronyc sources -v ; chronyc tracking    # 校時狀態
sudo hwclock -w                          # 系統時間 → 硬體時間
crontab -e ; crontab -l                  # 使用者排程
sudo vi /etc/crontab                     # 系統排程（有執行身份欄位）
sudo tail -f /var/log/cron               # 看排程有沒有跑
```
