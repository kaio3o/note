# 時間與系統排程

```bash
date
timedatectl
timedatectl list-timezones
timedatectl set-timezone Asia/Taipei
crontab -e
crontab -l
systemctl status chronyd
chronyc sources
```

時間會影響日誌比對、憑證、排程與分散式系統，因此應以 NTP／Chrony 維持同步。排程則要確認時區、執行使用者、環境變數、輸出位置與錯誤紀錄。

## 從零開始理解

伺服器時間不只是螢幕上的時鐘。日誌比對、TLS 憑證、資料庫紀錄、備份與排程都依賴正確時間；時間錯誤會讓「先發生的事情」看起來反而晚發生。

### 系統時間、時區與 NTP

- 系統時間：機器目前認為的時間。
- 時區：把 UTC 轉成人類所在地時間的規則。
- NTP/Chrony：和時間伺服器比較並逐步修正時鐘。

先查看：

```bash
date '+%F %T %z'
timedatectl
chronyc tracking
chronyc sources -v
```

設定台北時區：

```bash
sudo timedatectl set-timezone Asia/Taipei
sudo timedatectl set-ntp true
timedatectl
```

### cron 的五個欄位

```text
分  時  日  月  星期  指令
0   2   *   *   *     /usr/local/bin/backup.sh
```

代表每天凌晨 2:00 執行。常見符號：

- `*`：每一個。
- `*/5`：每 5 個單位。
- `1,15`：第 1 與第 15 個。
- `1-5`：範圍。

初學者常忘記 cron 的環境變數很少，因此腳本使用絕對路徑，並將輸出寫入日誌：

```cron
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
```

> [!warning] 先測試再排程
> 先手動執行腳本，確認退出碼與輸出，再放進 `crontab -e`。排程錯誤常常不是 cron 壞掉，而是路徑、權限或環境變數不同。
