# 訊息重導與管線

> [!abstract] 這章要學會什麼

## 一、先搞懂：程式有三條「水管」

每一個執行中的程式，都自帶三條資料通道：

```text
            ┌──────────────┐
 鍵盤 ──0──►│              │──1──► 螢幕（正常結果）
  stdin     │    程式       │  stdout
            │              │──2──► 螢幕（錯誤訊息）
            └──────────────┘  stderr
```

| 通道 | 代號 | 預設去向／來源 | 用途 |
|---|---|---|---|
| **stdin**（標準輸入） | 0 | 鍵盤 | 程式讀資料的地方 |
| **stdout**（標準輸出） | 1 | 螢幕 | 正常結果 |
| **stderr**（標準錯誤） | 2 | 螢幕 | 錯誤與警告 |

**問題來了**：stdout 與 stderr 預設都印在螢幕上，混在一起根本分不出來。例如 `foo` 指令印出 `Hello`，你看不出它是正常輸出還是錯誤。**重導（redirection）就是把這三條水管改接到別的地方**，讓你分類、保存、處理。

學會重導後，對日常維護、日誌分析、自動化腳本都非常有幫助。

## 二、重導符號總覽

| 符號 | 意思 | 範例 |
|---|---|---|
| `>` | stdout **覆蓋**寫入檔案 | `ls > out.txt` |
| `>>` | stdout **附加**到檔案結尾 | `ls >> out.txt` |
| `2>` | stderr 覆蓋寫入檔案 | `ls abc 2> err.txt` |
| `2>>` | stderr 附加到檔案 | `ls abc 2>> err.txt` |
| `<` | 讓檔案當作 stdin | `grep root < sample` |
| `2>&1` | 把 stderr 併到 stdout 現在去的地方 | `cmd > all.log 2>&1` |
| `&>` | Bash 縮寫：stdout + stderr 一起導 | `cmd &> all.log` |
| `/dev/null` | 黑洞，丟進去的東西直接消失 | `cmd 2> /dev/null` |
| `\|` | 管線：前者的 stdout → 後者的 stdin | `ls \| grep a` |

> [!warning] `2>` 中間不能有空格
> 要寫成 `2>file`（或 `2> file` 數字與 `>` 之間不能有空格）。如果寫成 `2 > file`，那個 `2` 會被當成一般參數。

## 四、輸入重導（stdin）

三種方式可以讓 `grep` 找到 `root`，**結果一樣，過程不同**：

```bash
grep root sample          # ① grep 自己打開檔案讀
grep root < sample        # ② Shell 打開檔案，從 stdin 餵給 grep
cat sample | grep root    # ③ cat 讀檔，透過管線餵給 grep
```

輸出都是：

```text
root:x:0:0:root:/root:/bin/bash
operator:x:11:0:operator:/root:/sbin/nologin
```

- ①：`grep` **知道**檔名，有些選項（如 `-H` 顯示檔名）因此可用。
- ②③：`grep` **不知道**資料從哪來，只是從 stdin 讀。這種「不管資料來源」的設計，就是 Unix 哲學：**每個程式只做好一件事，再用管線組合起來**。

> [!note] 這解釋了為什麼 `newusers < userlist`、`chpasswd < newpass.txt` 能運作
> 這兩個指令平時是從鍵盤讀（stdin），我們用 `<` 改成從檔案讀。（見 [[03 使用者與群組]]）

## 五、輸出重導（stdout）

```bash
ls -lh sample                  # 結果印在螢幕
ls -lh sample > stdout.txt     # 螢幕上什麼都沒有了 → 結果進了檔案
cat stdout.txt                 # -rw-r--r-- 1 student student 1.8K ... sample
```

這證明：`ls` 列出檔案的結果是 **stdout**。

### `>` 與 `>>` 的差別（重點）

- `>`：**先清空**檔案，再寫入。檔案不存在就建立（要有權限）。連跑 10 次，檔案裡永遠只有一行。
- `>>`：**保留原內容**，附加到最後面。

```bash
rm stdout.txt
ls -lh sample >> stdout.txt
ls -lh sample >> stdout.txt
ls -lh sample >> stdout.txt
cat stdout.txt            # 三行相同的內容
```

> [!danger] `>` 會無聲無息覆蓋檔案
> `echo hi > /etc/passwd` 就把帳號檔毀了。想防呆可以在 Bash 開 `set -o noclobber`，之後 `>` 遇到已存在的檔案會拒絕（要強制用 `>|`）。

## 六、錯誤重導（stderr）

故意列一個不存在的檔案：

```bash
ls sample2
# ls: cannot access sample2: No such file or directory   ← 這是 stderr
```

```bash
ls sample2 2> stderr.txt     # 螢幕乾淨了，錯誤被存進檔案
cat stderr.txt
```

附加用 `2>>`：

```bash
rm stderr.txt
ls sample2 2>> stderr.txt
ls sample2 2>> stderr.txt
ls sample2 2>> stderr.txt
cat stderr.txt               # 三行一樣的錯誤訊息
```

### 常見用法：把錯誤丟掉

```bash
find / -name '*.conf' 2> /dev/null     # 只看找到的，不看 Permission denied
```

## 七、整合重導（兩個通道一起處理）

### 1. 分開存

```bash
rm stdout.txt stderr.txt
ls sample2 > stdout.txt 2>stderr.txt
cat stdout.txt        # （空的）因為 ls sample2 失敗，沒有正常輸出
cat stderr.txt        # ls: cannot access sample2: ...
```

### 2. 全部存同一個檔：`2>&1`

```bash
ls sample2 > log.txt 2>&1
cat log.txt           # ls: cannot access sample2: ...
```

怎麼讀？**由左至右**處理：

1. `> log.txt`：stdout 先接到 `log.txt`。
2. `2>&1`：stderr 接到「stdout **現在**接的地方」→ 也進了 `log.txt`。

換成成功的指令，結果就是正常輸出：

```bash
ls sample > log.txt 2>&1
cat log.txt           # sample
```

> [!warning] 順序不能顛倒
> `cmd 2>&1 > log.txt` ❌ 錯誤：此時 stdout 還在螢幕，stderr 被接到螢幕，**之後**才把 stdout 改到檔案，所以錯誤還是出現在螢幕上。正確是 `cmd > log.txt 2>&1`，或直接用 `cmd &> log.txt`。

### 3. 全部附加存檔

```bash
rm log.txt
ls sample  >> log.txt 2>&1
ls sample2 >> log.txt 2>&1
cat log.txt
# sample
# ls: cannot access sample2: No such file or directory
```

這個寫法在 cron 排程裡幾乎天天看到：`/path/script.sh >> /var/log/x.log 2>&1`（見 [[07 時間與系統排程]]）。

## 八、管線（Pipe）`|`

### 概念

管線是一種**單向、匿名的管道**。把每個程式的輸出想成水流，用水管接到下一個程式的入口。

```text
 指令 A ──stdout──►  |  ──stdin──► 指令 B ──stdout──► 螢幕
```

規則：**只有 stdout 會流進管線，stderr 不會。**

### 範例

```bash
ls -lh sample | grep sample --color
# -rw-r--r-- 1 student student 1.8K Aug 25 16:44 sample   ← "sample" 被標紅色
```

紅色是 `grep` 加的，代表資料確實流到了 grep。

### 錯誤不會進管線

```bash
ls -lh sample2 | grep sample --color
# ls: cannot access sample2: No such file or directory    ← 完全沒有紅色
```

這行錯誤是 **stderr**，直接印到螢幕，**沒有**經過 `grep`。原教材說這代表「整個流程會停在有問題的階段」，其實更精確的說法是：管線裡每個程式是**同時**在跑的，只是 stderr 這條線沒有接進管線，grep 收到的是空的輸入。

### 想讓錯誤也一起進管線

```bash
ls -lh sample2 2>&1 | grep sample --color
# ls: cannot access sample2: No such file or directory   ← 這次 "sample" 變紅了
```

先 `2>&1` 把 stderr 併進 stdout，管線才收得到。（Bash 也有簡寫 `|&`。）

## 九、實用組合與範例

```bash
ps aux | grep nginx                       # 找出 nginx 的行程
cat access.log | grep 404 | less          # 看 404 的紀錄，分頁瀏覽
du -sh * | sort -h                        # 依大小排序各目錄用量
du -ah /var/log 2>/dev/null | sort -h | tail   # 忽略權限錯誤，列出最大的幾項
cut -d: -f1 /etc/passwd | sort | uniq -c  # 取帳號欄位、排序、統計
dnf repolist 2>&1 | tee dnf-check.log     # 螢幕看，同時存檔
```

### `tee`：同時顯示 + 存檔

管線像水管，`tee` 就是 T 字接頭：資料一路流下去，同時也「分一股」存到檔案。

```bash
command | tee result.log                 # 螢幕看 + 存檔（覆蓋）
command | tee -a result.log              # -a 附加
journalctl -p warning..alert -b | tee warnings.log | less
```

**常見用途**：`echo '...' | sudo tee /etc/xxx.conf`，解決「`sudo echo '...' > /etc/xxx` 失敗」的問題（因為 `>` 是由你當前的 shell 打開檔案，不是 sudo 的權限）。

### `xargs`：把管線的輸出變成「參數」

有些指令不看 stdin（如 `rm`、`cp`），需要 `xargs` 把前面的結果轉成參數：

```bash
find . -name '*.tmp' -print0 | xargs -0 rm -i
```

## 十、本章小抄

```text
>  覆蓋   >> 附加   2> 錯誤   2>&1 錯誤併進正常   &> 全部   < 檔案當輸入   | 管線   tee 分流
只有 stdout 會進管線；要帶錯誤就 2>&1
順序：cmd > file 2>&1   （不是 2>&1 > file）
```
