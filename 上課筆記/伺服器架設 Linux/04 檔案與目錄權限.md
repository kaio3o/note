## 一、權限的核心問題：「誰」可以對「什麼」做「什麼事」

Linux 裡每個東西（檔案、目錄、裝置）都有一組權限，回答三個問題：

- **誰**？→ UGO 三種角色
- **對什麼**？→ 這個檔案／目錄
- **做什麼**？→ rwx 三種動作

### UGO：三種角色

| 縮寫 | 全名 | 誰 |
|---|---|---|
| **u** | User | 擁有者（通常是建立它的人） |
| **g** | Group | 擁有這個物件的**群組**成員 |
| **o** | Others | **其他所有人**（不是擁有者、也不在該群組） |

還有一個 **a**（All）代表 u+g+o 全部，只用在 `chmod` 的符號寫法。

> [!tip] 判斷順序很重要
> 系統判斷你有沒有權限時，是**由左到右只看第一個符合的角色**：先看你是不是擁有者 → 是的話就只看 u 的權限（即使 o 比較寬鬆也沒用）；不是再看你在不在該群組 → 都不是才看 o。

### rwx：三種動作

| 符號             | 數字  | 對**檔案**            | 對**目錄**                |
| -------------- | --- | ------------------ | ---------------------- |
| **r**（Read）    | 4   | 讀取內容（`cat`、`less`） | 列出目錄裡有什麼（`ls`）         |
| **w**（Write）   | 2   | 修改內容               | 在裡面**新增、刪除、改名**項目      |
| **x**（Execute） | 1   | 當程式執行              | **進入**目錄（`cd`）、存取裡面的項目 |
| `-`            | 0   | 沒有這個權限             | 同左                     |

### 目錄的 r、w、x 是最容易搞混的

| 目錄權限 | 能做什麼 |
|---|---|
| `r-x` | 能 `cd` 進去、能 `ls` 列出內容 ✅（一般目錄的標準） |
| `--x` | 能 `cd` 進去、**不能列出**內容；但如果你**知道檔名**，還是能存取它 |
| `r--` | 能列出檔名，但**無法進入、也無法存取檔案**（很怪的組合，幾乎沒用） |
| `rwx` | 完整控制（可新增刪除檔案） |
| `-wx` | 能進去、能新增刪除，不能列出 |

> [!warning] 刪除檔案要看「目錄」的 w，不是檔案的 w
> 你想刪 `/class/a.txt`，需要的是 **`/class` 這個目錄**的 `w` 權限；就算 a.txt 本身權限是 `000`，只要你對目錄有 `w`（和 `x`）還是刪得掉。這也是 `/tmp` 要加「黏著位 sticky bit」（`drwxrwxrwt` 最後的 `t`）的原因：所有人都能寫，但只能刪自己的檔案。

## 二、數字權限（八進位）怎麼算？

`r=4`、`w=2`、`x=1`，把有的加起來：

| 符號 | 計算 | 數字 |
|---|---|---|
| `rwx` | 4+2+1 | **7** |
| `rw-` | 4+2+0 | **6** |
| `r-x` | 4+0+1 | **5** |
| `r--` | 4+0+0 | **4** |
| `--x` | 0+0+1 | **1** |
| `---` | 0 | **0** |

三組並排就是三位數。例如 `rwxr-xr--`：

- u：`rwx` = 7
- g：`r-x` = 5
- o：`r--` = 4
- 合起來是 **754**

（原教材這裡誤寫成「`75r`」，應是 `754`。）

> [!note] 為什麼說是「八進位」？
> `755`、`644` 這些其實是**八進位**數字（每一位 0–7，剛好用 3 個位元 rwx 表示）。我們習慣用十進位的眼光去看它，才會誤以為是普通數字。

### 常見權限速查

| 數字 | 符號 | 常用於 |
|---|---|---|
| `644` | `rw-r--r--` | 一般文件、網頁檔案 |
| `600` | `rw-------` | 私密檔（SSH 私鑰、含密碼的設定檔） |
| `755` | `rwxr-xr-x` | 程式、腳本、一般目錄 |
| `750` | `rwxr-x---` | 只給擁有者與群組用的程式／目錄 |
| `700` | `rwx------` | 私人目錄（如家目錄、`~/.ssh`） |
| `777` | `rwxrwxrwx` | ⚠️ 幾乎不該用 |

### 檔案與目錄要的最小權限

- 一個檔案要能**被執行**，需要 `r` + `x`（`r-x`）。（腳本因為要被直譯器讀，所以也要 r）
- 一個目錄想讓人**進入但不能列表**：`--x`。
- 想讓人**列表又能進入**：`r-x`。

## 三、變更擁有者與群組：`chown`、`chgrp`

```bash
chown alice file.txt              # 只改擁有者
chown alice:developers file.txt   # 擁有者 + 群組一起改
chown :developers file.txt        # 只改群組（冒號前面留空）
chown -R alice:developers dir/    # -R：整個目錄一路遞迴改
chgrp developers file.txt         # 只改群組
```

- **`chown` 通常只有 root 能用**（一般使用者不能把檔案送給別人）。
- `chgrp`：擁有者可以把檔案群組改成「自己所屬的」群組。
- 分隔符號用 `:` 或 `.` 都可以，建議用 `:`。

## 四、變更權限：`chmod`

### 方式 1：數字表示法

```bash
chmod 755 script.sh     # u=rwx, g=r-x, o=r-x
chmod 640 report.txt    # u=rw-, g=r--, o=---
```

### 方式 2：符號表示法（想只改某一部分時超好用）

格式：`chmod [角色][動作][權限] 檔案`

| 動作 | 意義 |
|---|---|
| `+` | 增加權限 |
| `-` | 移除權限 |
| `=` | 精確設定成這樣（其他的清掉） |

```bash
chmod u+x file          # 擁有者加上執行
chmod g-w file          # 群組拿掉寫入
chmod o=r file          # 其他人「只剩」讀取
chmod a+r file          # 所有人加讀取
chmod u=rwx,g=rx,o= file  # 一次設多個，用逗號分隔（o= 代表清空）
chmod -R 750 dir/       # 遞迴；用在目錄要小心
```

**什麼時候用哪種？** 要一次全部定案 → 數字；只想微調某一位 → 符號。

> [!tip] 大寫 X 的妙用
> `chmod -R u=rwX,g=rX,o= dir/`：`X`（大寫）只對**目錄**和**已經有 x 的檔案**加執行，避免把一般文字檔也變成可執行。

### 預設權限：`umask`

新建檔案不是 666 就是 777 的基礎再「扣掉」`umask`：

| | 基礎 | umask `022` 後 | umask `027` 後 |
|---|---|---|---|
| 新檔案 | 666 | 644 | 640 |
| 新目錄 | 777 | 755 | 750 |

`umask` 看目前設定，`umask 027` 修改（只對當前 shell 有效）。

## 五、實作：設計 `/class` 共用目錄

### 需求

建立 `/class`，底下三個子目錄，帳號與群組如下：

| 群組 | 成員 |
|---|---|
| `grp1` | user11、user12 |
| `grp2` | user21、user22 |

| 目錄 | 權限需求 |
|---|---|
| `/class/public` | 所有人都能寫入 |
| `/class/grp1` | 只有 grp1 群組可讀寫，**其他人完全沒權限** |
| `/class/grp2` | 只有 grp2 群組可讀寫，**其他人可讀取** |

### 步驟（需要 root）

**1. 建群組**

```bash
groupadd grp1
groupadd grp2
```

**2. 建帳號，主要群組指定好**

```bash
useradd -g grp1 user11
useradd -g grp1 user12
useradd -g grp2 user21
useradd -g grp2 user22
id user11 ; id user12 ; id user21 ; id user22    # 逐一檢查
```

**3. 建目錄**

```bash
mkdir /class
cd /class/
mkdir public grp1 grp2
ls -lh
```

**4. 設定 public：所有人都能寫**

```bash
chmod u=rwx,g=rwx,o=rwx public/        # 即 777
```

**5. 設定 grp1：群組讀寫、其他人沒權限**

```bash
chmod u=rwx,g=rwx,o=--- grp1           # 即 770
```

**6. 設定 grp2：群組讀寫、其他人可讀**

```bash
chmod u=rwx,g=rwx,o=rx grp2            # 即 775（目錄的「讀」要搭配 x 才有用，所以是 rx）
```

**7、8. 把目錄的群組指給對應群組**（**這步很容易漏！** 沒做的話目錄的群組還是 root，群組權限根本沒人用得到）

```bash
chgrp -R grp1 grp1/
chgrp -R grp2 grp2/
ls -lh
```

### 預期結果

```text
drwxrwxrwx. 2 root root hmm public    ← 所有人可寫
drwxrwx---. 2 root grp1 hmm grp1      ← 只有 grp1
drwxrwxr-x. 2 root grp2 hmm grp2      ← grp2 讀寫，其他人唯讀
```

### 驗證（一定要做！）

```bash
su - user11
touch /class/grp1/a.txt      # ✅ 成功（grp1 成員）
touch /class/grp2/b.txt      # ❌ Permission denied（對 grp2 來說是 other，只有 r-x）
ls /class/grp2               # ✅ 可以列出（other 有 r）
exit

su - user21
ls /class/grp1               # ❌ Permission denied（other 沒權限）
touch /class/grp2/c.txt      # ✅
```

> [!tip] 進階：讓目錄裡的新檔案自動繼承群組（SGID）
> 目前 user11 在 `/class/grp1` 建的檔案，群組是 user11 的主要群組（碰巧是 grp1）；但如果有人的主要群組不是 grp1，檔案的群組就會不對。對目錄設 SGID 後，裡面新建的東西會自動繼承目錄的群組：
> ```bash
> chmod g+s /class/grp1        # 或 chmod 2770 /class/grp1
> ```
> 而 `/class/public` 如果怕大家互相刪檔案，可以加黏著位：`chmod +t /class/public`（變成 `1777`）。

## 六、排查「Permission denied」的順序

```bash
ls -l file               # 1. 檔案本身的權限、擁有者、群組
namei -l /path/to/file   # 2. 一路檢查每一層父目錄有沒有 x
id                       # 3. 我是誰、屬於哪些群組（群組變更要重新登入）
getfacl file             # 4. 有沒有額外的 ACL 規則
ls -Z file               # 5. （進階）SELinux 標籤
```

很多時候檔案權限沒問題，卡的是**上層某個目錄沒有 x**。

## 七、進階小介紹：ACL

傳統 UGO 只能設「一個擁有者 + 一個群組 + 其他人」。要針對特定的人另外開權限，用 ACL：

```bash
setfacl -m u:alice:rw file     # 讓 alice 另外有 rw
getfacl file                   # 查看
setfacl -x u:alice file        # 移除
```

看到 `ls -l` 權限字串最後有個 `+`（`-rw-r--r--+`）就代表有 ACL。

> [!warning] 不要用 `chmod 777` 解決問題
> 它讓所有人都能讀、寫、執行，常常只是掩蓋真正的原因（擁有者、群組或上層目錄 x 設錯）。先用 `chown`、`chgrp`、ACL 解決。資安上「**最小權限原則**」＝只給剛好夠用的權限。
